A1 minimal方案 / scheme comparison
1. ASCII-only: very small, but excludes Chinese and ordinary human languages.
   Rejected as unnecessarily narrow for this project's recovery goal.
2. Hand-selected language blocks: compact but risks omitting ordinary languages,
   admitting unassigned holes, or excluding marks/composites needed for NFC.
   Rejected because it adds bespoke repertoire and closure decisions.
3. Fixed Unicode13 assigned-scalar repertoire: CHOSEN. Covers baseline languages,
   Chinese, common Latin accents/marks and baseline emoji. Source is the official
   13.0.0 UCD, the same baseline supported by the original Python reference.
   Exactly 679 sorted inclusive ranges / 281390 scalars after excluding surrogates
   and CR/LF. Compact ranges, not a normalization runtime/database in the browser.

Normative membership is printed completely in SPEC Appendix MP and mirrored in
master-phrase-repertoire.json and the reference/core literals. Future implementers
need no host category lookup, current chat or original source to decide legality.
Private-use (Co) included; unassigned/noncharacters excluded. Newer assignments
remain invalid. Validate ORIGINAL input before standard Unicode13 NFC, then UTF8.
Conformant NFC supporting Unicode13 or later gives the same output for these
baseline-assigned strings by Unicode normalization stability. No NFKC, stream-safe
CGJ insertion, trimming, case conversion or repair. Older/nonconformant runtimes
must fail; a Unicode13-era composition vector is included in browser startup.
The algorithm has a fixed input contract, not a frozen host/runtime dependency.
Official UnicodeData13 and NormalizationTest13 are archived for offline audit and
future implementation, with provenance/hashes/license. Never loaded by HTML.

Audit counterexample PUBLIC\u0897\u0323 is now invalid in both reference and JS
BEFORE Argon2. No attempt to preserve its previously conflicting passwords.
Original nine KDF vectors, classic three outputs and four Human vectors unchanged.

A2 implementation
Python norm and JS textScalar reject LF U+000A / CR U+000D anywhere before NFC,
UTF8/Argon2. CRLF is rejected, not normalized. Single-line input types retained.
Web examines raw text/plain clipboard/drop data, plus beforeinput data/linebreak
intent. Invalid edit is prevented, phrase/password cleared, explicit STOP shown,
derivation disabled. Rejection remains latched through any host-sanitized input
completion. Show/Hide does not release it. A subsequent explicit valid raw edit
allows retry. Missing readable clipboard data fails closed with manual-entry
instruction. Ordinary paste remains allowed. Programmatically supplied raw API
values must obey the same contract. The page cannot detect changes made to text
before it reaches the browser's clipboard event; no claim of OS input isolation.
