KDF-1 v1.0：Mac 第一次 GitHub 发布（本文件只指导，不自动上传）

准备的 KDF-1 文件夹是干净的公开快照，没有 .git 和旧历史。
所有测试秘密均公开；发布前不要往此目录放自己的恢复纸、密码或 QR。
release/ 里的 ZIP 和外部 SHA256SUMS 是稍后上传的 Release 附件。

推荐路径：GitHub Desktop 建仓库并上传，然后网页创建 Release。
不必先在 GitHub 网页另外创建同名仓库，避免出现两个仓库或初始文件冲突。

1. 如果没有账号，在 https://github.com/ 注册；按网页完成邮箱验证。
   从 https://desktop.github.com/ 安装 Mac 版 GitHub Desktop 并登录。
   这只是发布准备；恢复用户不需要 GitHub Desktop 或联网。
2. 在 Desktop 选择 File → New Repository。
   Name 填 KDF-1；Local path 选择一个新的普通文件夹（例如 Documents/GitHub）。
   Desktop 会在所选位置下面新建 KDF-1 子文件夹，不要选本交付文件夹的父目录。
   不勾选 Initialize with README；Git ignore 与 License 都选 None。
   我们已有完整 README/LICENSE/.gitignore，不需要自动生成第二套。
3. 用 Finder 打开新建的仓库文件夹。把本交付 KDF-1 里面的所有内容复制进去。
   不要复制成 KDF-1/KDF-1 两层；打开后应直接看到 RECOVER.html、SPEC.txt。
   按 Command+Shift+. 显示隐藏文件，确保 .gitignore 也复制过去。
   保留 Desktop 新建的 .git；不要从其他项目复制 .git 或旧历史。
4. 返回 Desktop 的 Changes。检查只有公开项目文件，没有私人恢复材料。
   release ZIP 和外部 release/SHA256SUMS 被 .gitignore 排除是正常的；
   它们稍后作为 Release 附件上传。根目录 SHA256SUMS 和 INTEGRITY 要提交。
   填 summary：KDF-1 v1.0 frozen publication。点击 Commit to main
   （若分支叫其他名字，以实际名称为准）。Commit 是本地文件快照，还没公开。
   新建空仓库可能已有一个初始空 commit，不影响干净历史。
5. 点击 Publish repository。名字 KDF-1；取消 Keep this code private，
   表示你有意公开。检查一次内容后再点击 Publish Repository。
   这一步才把文件上传到 GitHub。不需要命令行或额外创建远程。
   若你已在网页创建同名仓库，不要强行覆盖：使用新的空名称，或先弄清已有内容。
   网页创建仓库时也应不勾选自动 README、LICENSE、.gitignore。
6. Desktop → Repository → View on GitHub。确认首页直接有 README、SPEC、
   RECOVER.html、FREEZE.txt、reference、developer、licenses 等。
   点击几个文件确认内容；不要仅看到一个套在外面的 KDF-1 文件夹。
7. 网页右侧 Releases → Draft a new release（或 Create a new release）。
   Choose a tag 中输入 v1.0，选择 Create new tag；Target 选择刚上传的 main
   （或实际分支），确认是冻结提交。Tag 是给这一份提交的固定版本标签。
   不要把未来新内容移到这个标签。
8. Release title 填：KDF-1 v1.0 — Frozen
   把 release/RELEASE_NOTES.md 内容复制到说明区。
   将 release/KDF-1-v1.0-FROZEN.zip 和 release/SHA256SUMS.txt
   拖到附件区域，等待两份上传完。不把这两份放进源代码 commit。
   不勾选 pre-release。可先 Save draft 检查，再 Publish release。
   如果启用了 immutable releases，必须先把附件放齐再发布。
9. 打开 Release 页面确认标题、v1.0 和两个具名附件都在。
   GitHub 自动的 Source code ZIP 不是我们已验证的具名恢复包。
   下载 KDF-1-v1.0-FROZEN.zip 和 SHA256SUMS.txt；解压具名 ZIP，
   打开 START_HERE.txt，再用 RECOVER.html 等待 SELF TEST PASS。
   第一次只使用公开测试数据，不在公开页面输入真实秘密。
10. SHA256SUMS 是文件损坏/意外变化检查，不是发布者数字签名。
    若希望自己核对下载 ZIP，可在 Mac Terminal 输入 shasum -a 256 后留空格，
    把下载的 ZIP 拖进去再回车，与外部 SHA256SUMS 第一行比较。
    这是可选发布核验，不是普通恢复所需的安装/命令步骤。
11. 发布后可以自行启用 GitHub Private vulnerability reporting：
    仓库 Settings 的安全设置内找到 Private vulnerability reporting 并启用。
    页面位置变化时按下方官方文档查找；本次没有代你改设置或虚构联系邮箱。
12. 以后在你的账号 → KDF-1 → Releases → v1.0 下载同名恢复包。
    自己另外保存离线副本，灾难时不应只依赖 GitHub 或互联网。
    不覆盖/替换 v1.0 的文件、附件或 tag。未来 KDF-2 最简单另开一个仓库，
    使用新协议名、新规范和新 vectors；保留 v1.0 的恢复兼容性。
